# Política de software del workspace estándar
Proyecto: ASIR_Mission Start – NextGen Web Solutions

## 1. Objetivo
Definir el software permitido, recomendado y no permitido en los workspaces estándar con el fin de mejorar el rendimiento, la estabilidad y la compatibilidad del entorno.

---

## 2. Software base obligatorio

| Software | Versión recomendada | Observaciones |
|--------|--------------------|--------------|
| Sistema operativo | Windows 11 Pro / Linux LTS | Última versión estable |
| Navegador web | Chrome / Firefox | Actualizado |
| VS Code | Última versión estable | Desarrollo |
| Suite ofimática | LibreOffice / Microsoft 365 | Uso general |
| Antivirus | Corporativo | Protección obligatoria |

---

## 3. Software recomendado por perfil

### Desarrollo
- Node.js (LTS)
- Git (última versión)
- Docker Desktop (si aplica)

### Diseño
- Figma Desktop
- Photoshop (versión estable)

### Gestión
- Herramientas de gestión web
- Cliente de correo corporativo

---

## 4. Software no permitido

| Software | Motivo |
|--------|-------|
| Aplicaciones P2P | Consumo excesivo de recursos |
| Software sin licencia | Riesgo legal |
| Aplicaciones obsoletas | Incompatibilidad |
| Juegos | Uso no productivo |

---

## 5. Control de versiones

- Uso de versiones LTS o estables
- Actualizaciones periódicas controladas
- Prohibidas versiones beta o experimentales

---

## 6. Conclusión

La estandarización del software reduce errores, incompatibilidades y consumo innecesario de recursos, mejorando la estabilidad de los workspaces.
